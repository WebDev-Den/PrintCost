# Збережений стан і решта завдань KILO·G

Дата: **9 жовтня 2026**. Нова команда **«продовжуй виконувати задачі які не довиконував перевір чи все ок»** відновила реалізацію та перевірки. Кожен блок завершити й перевірити перед наступним. Попередня пауза після відключення світла завершена; production-активація й злиття `main` лишаються окремим етапом готового релізу.

## Поточний стан

- Робоча гілка: `codex/user-platform`, репозиторій `WebDev-Den/PrintCost`. Не зливати в `main`: його відстежує Cloudflare Builds.
- REST API реалізований локально: особисті ключі адміністратора/менеджера, створення/ротація/відкликання, JSON-імпорт, стабільне оновлення за `externalId`, компанії адміністратора й автоматичне створення за доменом товару, поточні права й дозволені домени менеджера, підбір стандартного/власного профілю пластику.
- Додані вкладка `/app/api`, документація, завантаження JSON, статуси та результати імпорту; звичайний користувач доступу не має. Пропущені необов'язкові поля під час оновлення зберігаються.
- Черга обробляє до 5 записів за доставку послідовно. D1 outbox, квитанції Firestore та idempotency захищають від втрати завдання й повторного застосування записів.
- Межі: 100 записів / 128 KiB за запит; менеджер раз на годину, адміністратор раз на 5 хвилин; один активний імпорт на користувача; спільно за UTC-добу 5000 записів, 100 завдань, 1000 перевірок доступу й 1500 відправлень черги. Строк ключа 90 днів, завдання 24 години, історія 30 днів.
- Нові міграція `migrations/0002_import_api.sql`, Queue `kilog-imports`, секрет `FIREBASE_IMPORT_SERVICE_ACCOUNT` та конфігурація Worker підготовлені **лише в коді**. Production інфраструктуру цього API не активовано.
- Попереднє перенесення Google-входу й CAPTCHA вниз форми також збережене в Git, ще не опубліковане.
- Production під час цієї роботи не змінювався. Останній зафіксований активний Worker: `79fccdd2-049f-4c52-8eac-e8251ccc2941`, source `d03c1226d4a985e2d379c27279d6b49d123a9a17`; адреса `https://web-dev.pp.ua`.

## Уже виконані перевірки

- Lint, 131 тест застосунку, production build, deployment validator і Wrangler dry-run пройшли.
- Повний запуск локальних emulator/integration tests: 100 PASS. Окремо перевірені остання неоднозначна відповідь commit, недоступна відправка в Queue, конкурентні квоти, ротація без скидання cooldown та відкликання доступу.
- Локальний браузер: менеджер імпортував JSON, отримав completed / 1 success і побачив товар у своїй компанії; звичайний користувач перенаправлений з API; адміністратор бачить документацію компаній. Це ізольовані тестові акаунти, без live writes.
- Після повного інтеграційного запуску були невеликі зміни перевірки native limiter за UID/IP, запиту списку завдань та UI. Повний інтеграційний повтор для остаточного стану ще не зроблений. Після команди зупинки нових тестів не запускати.
- Завершення чутливої повторної авторизації та ротації ключа через UI ще не прийняте наскрізно; серверні маршрути перевірені тестами.
- Локальні логи, допоміжні fixture-файли, скриншоти та будь-які credentials лишаються в ігнорованому `output/`; тести й інструкції збережені в репозиторії.

## Невиконані завдання — тільки після нової команди

Окрема команда дозволила **підготовку дизайну email-шаблонів і пояснення власного відправника**. Виконано [пакет із трьома HTML/текстовими версіями та інструкцією](./docs/email-templates/README.md), перевірено структуру й ширину 320 px. Підключення макетів, надсилання листів, Firebase/DNS/SMTP і деплой не виконувалися; ця робота не поновлює інші задачі.

- [ ] Після команди на застосування налаштувати ім'я KILO·G, теми та дозволені тексти в Firebase Templates. Для `noreply@web-dev.pp.ua` отримати точні записи через Customize domain, перевірити наявні MX/SPF, додати сумісні TXT і DNS-only CNAME, завершити verification / Apply Custom Domain. Перевірити справжні листи й SPF/DKIM.
- [ ] Якщо потрібне повне оформлення всіх листів, окремо погодити й підключити власний сервіс доставки та серверну генерацію action links з урахуванням безкоштовних лімітів. Перед використанням шаблона зміни адреси завершити `recoverEmail` handler або зберегти штатний Firebase handler. Макети не є інтеграцією.

Нова команда користувача дозволила **перевірку безпеки**; вона завершена окремим звітом [security_best_practices_report.md](./security_best_practices_report.md). Це не дозвіл відновлювати решту реалізації або деплой. 60 цільових app/Worker tests + 65 Rules/Firestore/D1/Queue checks пройшли. Підтверджений недолік спільної квоти: user з HTTP 403 витрачає privileged daily access budget, через що admin отримує 429. Функціональний код не змінений.

- [x] SEC-001 виправлено локально: персональний лічильник до Firebase, окремі бюджети 500 manager / 500 admin, відмови не витрачають резерв. Додано реальний D1/Worker regression для багатьох 403, персонального overflow без Firebase reads, резерву адміністратора та конкурентних запитів. TypeScript і цільова інтеграція PASS. Міграція 0003 ще не застосована в production.
- [ ] Після нової команди опрацювати SEC-002–005 зі звіту: прямі Firebase Auth запити поза CAPTCHA, Firestore quota abuse, CSP, development dependencies. Не вмикати paid plan й не застосовувати сліпий `npm audit fix --force`.
